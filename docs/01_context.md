# 1. Контекст, проблема, стейкхолдеры

> Учебный кейс. Интернет-магазин «Ромашка-Маркет» вымышленный, данные синтетические (`data/`). Платёжный сервис — реальный публичный API ЮKassa; в README указано, что проверялось, а что нет.

## Компания
Онлайн-магазин товаров для дома, ~2 000 заказов в месяц, 65 % — с телефона. Приём платежей через ЮKassa, только карта и кошелёк ЮMoney. Возвраты оператор поддержки делает вручную в личном кабинете ЮKassa.

## Проблема (со слов коммерческого директора)
«Треть мобильных покупателей не доходит до оплаты. Клиенты жалуются, что с них списали дважды. Возврат ждут по 2–4 дня. А ещё банк пишет, что с осени нужно принимать цифровой рубль».

## Гипотезы и цели
| # | Гипотеза | Цель (через 2 месяца после запуска) |
|---|---|---|
| H1 | Оплата по QR СБП на мобильном убирает 3-DS: покупатель подтверждает в приложении банка | Конверсия мобильных 80 → **86 %** |
| H2 | Ключ идемпотентности на создание платежа убирает двойные списания | Двойных списаний **0** |
| H3 | Обработка webhooks вместо опроса | Статус «оплачен» ≤ **1 мин** (p95) |
| H4 | Возврат через API по кнопке оператора, без личного кабинета | Медиана возврата ≤ **4 ч** |
| H5 | Подготовка к цифровому рублю как третьему способу | Требования готовы к запуску способа |

## Рамки
**Входит:** создание платежа (карта, СБП, кошелёк), подтверждение, webhooks, статусы, чек 54-ФЗ через платёжный сервис, полный и частичный возврат, требования к цифровому рублю.
**Не входит:** рассрочка и BNPL, подписки (рекуррентные платежи), фискализация на своей кассе, выбор другого платёжного провайдера.

## Стейкхолдеры
| Стейкхолдер | Интерес | Влияние | Что важно |
|---|---|---|---|
| Коммерческий директор | Конверсия, выручка | Высокое | Рост мобильной конверсии |
| Финансовый директор | Комиссии, сверка, цифровой рубль | Высокое | Комиссия СБП ниже карточной |
| Покупатель | Быстро и без двойных списаний | — | Понятная ошибка и второй способ |
| Поддержка | Меньше обращений «списали дважды», быстрые возвраты | Среднее | Кнопка возврата в админке |
| Бэкенд-разработчики | Ясный контракт и обработка ошибок | Высокое | OpenAPI, sequence, статусы |
| Склад | Не собирать неоплаченное | Среднее | Статус «оплачен» без задержки |
| Платёжный сервис (ЮKassa) | — | Высокое (внешний) | Его API и ограничения задают рамки |
| ОФД / ФНС | Чеки 54-ФЗ | Высокое (регулятор) | Чек на оплату и на возврат |
| НСПК / Банк России | Правила СБП и цифрового рубля | Высокое (регулятор) | Требования к QR и срокам |
