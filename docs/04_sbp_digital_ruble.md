# 4. СБП и цифровой рубль как новые способы оплаты

> **Учебная модель, не копия протоколов НСПК и платформы цифрового рубля.** Цифры и сроки — по открытым источникам на осень 2026, перед использованием проверить на сайтах Банка России и НСПК.

## 4.1. Чем три способа отличаются для магазина
| | Банковская карта | QR / ссылка СБП (C2B) | Цифровой рубль |
|---|---|---|---|
| Кто подтверждает | 3-DS на странице банка | покупатель в приложении своего банка | покупатель в приложении банка, деньги с цифрового кошелька |
| Где риск отказа | 3-DS, лимиты карты, антифрод | не вернулся из приложения, лимит СБП | нет кошелька / нет цифровых рублей |
| Когда деньги у магазина | через эквайрера, обычно на следующий день | обычно быстро (зависит от банка магазина) | зачисление на счёт магазина |
| Комиссия для магазина | договорная, обычно выше | регулируется Банком России, ниже карточной | заявлена Банком России как низкая (проверить актуальную) |
| Chargeback (оспаривание покупателем) | есть | нет, возврат делает только магазин | нет, возврат делает только магазин |
| Возврат | на ту же карту | отдельной операцией по реквизитам платежа | отдельной операцией |

## 4.2. Почему СБП должен помочь мобильной конверсии
32 % отказов — это `3d_secure_failed`, ещё 20 % — «не подтвердил вовремя» (`sql/02_decline_reasons.sql`). На телефоне покупатель уходит из браузера в SMS или приложение банка и часто не возвращается. В СБП подтверждение и есть приложение банка — шаг 3-DS исчезает. **Гипотеза, а не факт:** проверять A/B-тестом (50 % мобильных видят СБП первым).

## 4.3. Требования к оплате через СБП
- QR **динамический** (сумма зашита в код, один QR — одна покупка), срок жизни — 10 минут (BR-03).
- На мобильном вместо QR — список банков с переходом в приложение (deeplink).
- Возврат по СБП — отдельная операция возврата через провайдера, не «отмена платежа».
- Повторное сканирование того же QR не должно создать второй платёж (за это отвечает провайдер/НСПК; мы проверяем статус по `payment_id`).

## 4.4. Требования к цифровому рублю (подготовка)
- **Регуляторный контекст** (по открытым источникам): по предложению Банка России обязательный приём цифрового рубля вводится поэтапно с 01.09.2026 для крупных продавцов, обслуживающихся в крупнейших банках, затем для продавцов с меньшей выручкой; универсальный QR-код банки должны поддержать к 01.09.2026. Магазин с выручкой ~10 млн ₽ в месяц должен уточнить, когда обязанность наступит для него.
- **Что нужно от провайдера:** поддержка способа «цифровой рубль» в API платежей, статусы и возвраты в той же модели, что у СБП.
- **Изменения у нас:** новый `method = digital_rub` в API и БД, текст на экране оплаты, отдельная строка в отчёте по комиссиям, отдельный KPI доли.
- **Открытые вопросы:** нужен ли отдельный учёт зачислений в 1С; как выглядит чек; какие лимиты операций.

## 4.5. Риски
| Риск | Что делаем |
|---|---|
| Покупатель не возвращается из приложения банка после СБП | Страница ожидания с таймером + страховочный опрос статуса (US-03) |
| Провайдер не поддерживает цифровой рубль к сроку | Зафиксировать в договоре сроки; альтернативный провайдер — вне рамок |
| Рост возвратов без chargeback — споры уходят в поддержку | Регламент возвратов, KPI времени возврата |
